# Vim 模式

Zed 内置了名为“vim 模式”的 Vim 模拟功能。本页面将指导您如何启用或禁用 Zed 的 vim 模式，了解 Zed 提供了哪些工具和命令来帮助您浏览和编辑代码，以及如何充分发挥 vim 模式在 Zed 中的效能。

您将学习如何：

- 理解 Zed 的 vim 模式与传统 Vim 的核心差异
- 启用或禁用 vim 模式
- 在 vim 模式下充分利用 Zed 的专属功能
- 自定义 vim 模式快捷键绑定
- 配置 vim 模式设置

无论您是 vim 模式的新手，还是希望优化 Zed 使用体验的资深 Vim 用户，本指南都将帮助您掌握 Zed 中模态编辑的全部潜能。

## Zed 的 vim 模式设计理念

Vim 模式致力于为 Vim 用户提供熟悉的操作体验：在适用场景下精准复现 Vim 的移动指令与命令行为，同时结合 Zed 的专属功能，打造开箱即用、无需额外配置的编辑体验。

这包括对语义导航、多光标或环绕文本等通常由插件提供的功能的支持。

因此，Zed的vim模式并非与Vim完全一一对应，而是将Vim的模态设计与Zed的现代功能相融合，以提供更流畅的体验。它还具有可配置性，你可以添加自定义键位绑定或覆盖默认设置。

### 核心差异

vim模式中有四类功能采用了Zed的核心机制，这导致了一些行为差异：

1. **移动操作**：Vim模式利用Zed的语义解析功能，针对不同编程语言优化移动操作行为。例如在Rust中，使用`%`跳转到匹配括号时，可兼容管道符`|`；而在JavaScript中，`w`会将`$`识别为单词字符。
2. **可视化块选择**：Vim模式通过Zed的多光标系统模拟可视化块选择功能，使块选择操作更加灵活。例如在块选择后插入内容时，所有选定行都会实时同步更新，且支持随时增减光标数量。
3. **宏功能**：Vim模式依托Zed的录制系统实现Vim宏操作。这意味着您可以录制并回放更复杂的操作流程，例如代码自动补全过程。
4. **搜索替换**：Vim模式集成Zed的搜索系统，其正则表达式语法与标准Vim存在细微差异。具体区别请[参阅正则表达式差异章节](#regex-differences)。

> **注意：** Zed 的 Vim 模式基础功能已覆盖多数使用场景，我们也在持续优化改进。如果在工作流中遇到缺失的关键功能，请[前往 GitHub 提交问题报告](https://github.com/zed-industries/zed/issues)。

## 启用与禁用 Vim 模式

首次启动 Zed 时，欢迎界面会提供启用 Vim 模式的勾选选项。

若初始未设置，您随时可通过命令面板调用工作区命令 `toggle vim mode` 来切换 Vim 模式的开关状态。

> **注意：** 该命令会切换您用户设置中的以下属性：
>
> ```json [settings]
> {
>   "vim_mode": true
> }
> ```

### 支持的插件

Zed 的 Vim 模式包含了一些在 Vim 生态系统中通常由非常流行的插件提供的功能：

- 你可以使用 `ys` 环绕文本对象（复制环绕），用 `cs` 更改环绕内容，用 `ds` 删除环绕内容。
- 在可视模式下，你可以使用 `gc` 注释或取消注释选中内容，在普通模式下使用 `gcc`。
- 项目面板支持许多基于 Vim 插件 `netrw` 的快捷键：使用 `hjkl` 进行导航，使用 `o` 打开文件，使用 `t` 在新标签页中打开文件等。
- 你可以将按键绑定添加到键位映射中，以便在“驼峰命名法”的名称之间导航。请参阅[可选按键绑定](#可选按键绑定)部分了解具体方法。
- 你可以使用 `gR` 实现 [ReplaceWithRegister](https://github.com/vim-scripts/ReplaceWithRegister) 功能。
- 你可以使用 `cx` 实现 [vim-exchange](https://github.com/tommcdo/vim-exchange) 功能。请注意，在可视模式下它没有默认绑定，但你可以将其添加到键位映射中（参考[可选按键绑定](#可选按键绑定)部分）。
- 你可以使用 [indent wise](https://github.com/jeetsukumaran/vim-indentwise) 插件 `[-`、`]-`、`[+`、`]+`、`[=`、`]=` 根据光标的相对缩进深度进行导航。
- 你可以使用 AnyQuotes 选择引号内的文本，使用 AnyBrackets 选择括号内的文本。Zed 还提供了 MiniQuotes 和 MiniBrackets，它们基于 [mini.ai](https://github.com/echasnovski/mini.nvim/blob/main/readmes/mini-ai.md) Neovim 插件提供替代的选择行为。详情请参阅下面的[引号和括号文本对象](#引号和括号文本对象)部分。
- 你可以配置 AnyQuotes、AnyBrackets、MiniQuotes 和 MiniBrackets 文本对象，使用不同的选择策略来选择引号和括号内的文本。详情请参阅下面的[任意括号功能](#任意括号功能)部分。

### 任意括号功能

Zed 提供两种不同的策略来选择被任意引号或任意括号包围的文本。这些文本对象**默认未启用**，需要在按键映射中进行配置才能使用。

#### 包含字符

每种文本对象类型对应特定字符：

| 文本对象              | 字符                                                                             |
| ------------------------ | -------------------------------------------------------------------------------------- |
| 任意引号/迷你引号     | 单引号 (`'`)、双引号 (`"`)、反引号 (`` ` ``)                             |
| AnyBrackets/MiniBrackets | Parentheses (`()`), Square brackets (`[]`), Curly braces (`{}`), Angle brackets (`<>`) |

"任意"和"迷你"变体使用相同的字符集，但选择策略不同。

#### 任意引号与任意括号（传统 Vim 行为）

这些文本对象实现了传统 Vim 的行为：

- **选择优先级**：优先查找最内层（最近）的引号或括号
- **回退机制**：若未找到匹配项，则回退至当前行
- **基于字符的匹配**：仅关注开合字符，不涉及语法分析
- **原生Vim相似性**：AnyBrackets完全复现原生Vim中`ci<`、`ci(`等命令的行为，包括特殊边界情况处理（例如将`=>`中的`>`识别为闭合分隔符）

#### MiniQuotes与MiniBrackets（mini.ai行为模式）

这些文本对象实现了[mini.ai](https://github.com/echasnovski/mini.nvim/blob/main/readmes/mini-ai.md) Neovim插件的核心功能：

- **选择优先级**：优先搜索当前行内容，再向外扩展范围
- **语法树集成**：通过Tree-sitter查询实现上下文感知选择
- **语法感知匹配**：能准确区分真实括号与特殊语境中的相似字符（例如识别`=>`中的`>`）

#### 方案选择指南

- 在以下情况下使用 **AnyQuotes/AnyBrackets**：

  - 偏好传统 Vim 行为
  - 需要以字符为基础、优先选择最内层分隔符的一致性选取方式
  - 要求行为与原生 Vim 文本对象高度吻合

- 在以下情况下使用 **MiniQuotes/MiniBrackets**：
  - 偏好 mini.ai 插件的行为逻辑
  - 希望通过 Tree-sitter 实现更智能的上下文感知选取
  - 在搜索时优先考虑当前行范围

#### 配置示例

要使用这些文本对象，您需要在键位映射中添加绑定。以下示例配置使它们可在文本对象操作符（`i` 和 `a`）或变更环绕符（`cs`）时调用：

```json [settings]
{
  "context": "vim_operator == a || vim_operator == i || vim_operator == cs",
  "bindings": {
    // Traditional Vim behavior
    "q": "vim::AnyQuotes",
    "b": "vim::AnyBrackets",

    // mini.ai plugin behavior
    "Q": "vim::MiniQuotes",
    "B": "vim::MiniBrackets"
  }
}
```

完成配置后，您即可使用如下命令：

- `cib` - 使用任意括号行为修改括号内内容  
- `ciB` - 使用迷你括号行为修改括号内内容  
- `ciq` - 使用任意引号行为修改引号内内容  
- `ciQ` - 使用迷你引号行为修改引号内内容

## 自定义按键绑定

本节将学习如何自定义 Zed 编辑器 Vim 模式的按键绑定。您将掌握：

- 如何为新按键绑定选择正确的上下文环境
- Vim 模式按键绑定的实用上下文配置
- 提升效率的常用自定义按键绑定方案

### 选择正确的上下文环境

Zed 的按键绑定仅在 `"context"` 属性与您在编辑器中的位置匹配时生效。例如：
- 若将按键绑定添加至 `"Editor"` 上下文，则仅在编辑文件时生效
- 若将按键绑定添加至 `"Workspace"` 上下文，则在 Zed 全域生效

以下示例展示了在编辑文件时的保存按键绑定配置：

上下文是嵌套的，因此当你编辑文件时，当前处于`"Editor"`上下文，该上下文包含于`"Pane"`上下文，而后者又包含于`"Workspace"`上下文。这就是为什么你添加到`"Workspace"`上下文的任何键位绑定都会在编辑文件时生效。示例如下：

```json [keymap]
// This key binding will work when you're editing a file. It comes built into Zed by default as the workspace: save command.
{
  "context": "Workspace",
  "bindings": {
    "ctrl-s": "workspace::Save"
  }
}
```

上下文本质是表达式，支持布尔运算符如`&&`（逻辑与）和`||`（逻辑或）。例如，你可以使用`"Editor && vim_mode == normal"`上下文来创建仅在编辑文件且处于Vim普通模式时生效的键位绑定。

Vim模式会向`"Editor"`上下文添加若干子上下文：

| 操作符               | 描述                                                                                                                                                                               |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| VimControl           | 表示应启用Vim键位绑定。当前为`vim_mode == normal \|\| vim_mode == visual \|\| vim_mode == operator`的别名，但定义可能随时间变化                                                                      |
| vim_mode == normal   | 普通模式                                                                                                                                                                           |
| vim_mode == visual   | 可视模式                                                                                                                                                                           |
| vim_mode == insert   | 插入模式                                                                                                                                                                           |
| vim_mode == replace  | 替换模式                                                                                                                                                                           |
| vim_mode == waiting  | 等待任意按键（例如输入`f`或`t`后）                                                                                                                       |
| vim_mode == operator | 等待触发其他绑定（例如输入`c`或`d`后）                                                                                                                   |
| vim_operator         | 默认设为`none`；若`vim_mode == operator`成立，则设为当前操作符的默认键位绑定（例如输入`d`后，`vim_operator == d`）                                                   |

> **注意**：上下文每次仅匹配一个层级。因此可以使用表达式 `"Editor && vim_mode == normal"`，但 `"Workspace && vim_mode == normal"` 永远不会匹配，因为我们将 vim 上下文设置在 `"Editor"` 层级。

### Vim 模式键位绑定的实用上下文

以下模板提供实用的 vim 模式上下文，助您自定义 vim 模式键位绑定。您可以复制该模板并整合到您的用户键位映射中。

> **注意**：如果您想要模拟 Vim 的 `jk` 命令（`djk` 等），可以在正确的上下文中使用 `editor.action.deleteLines` 操作。

### 可选键位绑定

默认情况下，你可以使用快捷键在编辑器中打开的不同文件之间导航，例如先按`ctrl+w`，再按`hjkl`中的某个键，分别向左、下、上或右移动。

但你不能使用相同的快捷键在所有编辑器面板（终端、项目面板、助手面板等）之间移动。如果你想使用相同的快捷键导航到这些面板，可以将以下键绑定添加到你的用户键映射中。

```json [settings]
{
  "context": "Dock",
  "bindings": {
    "ctrl-w h": "workspace::ActivatePaneLeft",
    "ctrl-w l": "workspace::ActivatePaneRight",
    "ctrl-w k": "workspace::ActivatePaneUp",
    "ctrl-w j": "workspace::ActivatePaneDown"
    // ... or other keybindings
  }
}
```

子词移动功能默认未启用，它允许你在驼峰命名法或蛇形命名法中导航并选择单个单词。要启用此功能，请将这些绑定添加到你的键映射中。

Vim 模式在普通模式下提供了环绕选区的快捷键（`ys`），但在可视模式下没有默认的环绕快捷键。默认情况下，`s` 会替换选区（删除文本并进入插入模式）。若要在可视模式下使用 `s` 添加环绕符号，可将以下对象添加到键位映射中：

```json
{
  "contexts": ["Editor", "Terminal"],
  "bindings": {
    "v": {
      "s": ["workspace::Surround", "workspace::Surround"]
    }
  }
}
```

在非模态文本编辑器中，光标导航通常会在越过行尾时自动换行。然而 Zed 默认与 Vim 的处理方式完全一致：光标会在行边界处停止。如果您希望光标在行间自动换行，可覆盖以下键位绑定：

```json
{
  "bindings": {
    "left": ["editor::MoveLeft", "editor::MoveLeft"],
    "right": ["editor::MoveRight", "editor::MoveRight"]
  }
}
```

[Sneak 移动功能](https://github.com/justinmk/vim-sneak) 能够快速跳转到文本中的任意两个字符序列。你可以通过将以下按键绑定添加到按键映射中来启用它。默认情况下，`s` 键被映射为 `vim::Substitute`。添加这些绑定将覆盖原有行为，因此请确保这一调整符合你的工作流程偏好。

```json [settings]
{
  "context": "vim_mode == normal || vim_mode == visual",
  "bindings": {
    "s": "vim::PushSneak",
    "shift-s": "vim::PushSneakBackward"
  }
}
```

[vim-exchange](https://github.com/tommcdo/vim-exchange) 功能在可视模式下没有默认绑定，因为 `shift-x` 绑定与可视模式下的默认 `shift-x` 绑定（`vim::VisualDeleteLine`）冲突。要分配默认的 vim-exchange 绑定，请将以下按键绑定添加到你的按键映射中：

```json [settings]
{
  "context": "vim_mode == visual",
  "bindings": {
    "shift-x": "vim::Exchange"
  }
}
```

### 恢复常用文本编辑和 Zed 按键绑定

如果你在 Linux 或 Windows 上使用 vim 模式，可能会发现它覆盖了一些你离不开的按键绑定：`ctrl+v` 用于粘贴，`ctrl+f` 用于搜索等。你可以通过将这些数据复制到你的按键映射中来恢复它们：

```json [keymap]
{
  "context": "Editor && !menu",
  "bindings": {
    "ctrl-c": "editor::Copy",               // vim default: return to normal mode
    "ctrl-x": "editor::Cut",                // vim default: decrement
    "ctrl-v": "editor::Paste",              // vim default: visual block mode
    "ctrl-y": "editor::Undo",               // vim default: line up
    "ctrl-f": "buffer_search::Deploy",      // vim default: page down
    "ctrl-o": "workspace::Open",            // vim default: go back
    "ctrl-s": "workspace::Save",            // vim default: show signature
    "ctrl-a": "editor::SelectAll",          // vim default: increment
    "ctrl-b": "workspace::ToggleLeftDock"   // vim default: down
  }
},
```

## 适用于 Vim 模式的核心 Zed 实用设置

以下是一些通用的 Zed 设置，可以帮助你优化 Vim 的使用体验：

| 属性                   | 描述                                                                                                                                                             | 默认值               |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------- |
| cursor_blink           | 若设为`true`，光标将闪烁显示                                                                                                                                    | `true`               |
| relative_line_numbers  | 若设为`true`，左侧装订线中的行号将相对于光标位置显示                                                                                                               | `false`              |
| scrollbar              | 控制滚动条显示的对象。设为`{ "show": "never" }`可隐藏滚动条                                                                                                                   | `{ "show": "auto" }` |
| scroll_beyond_last_line| 若设为`"one_page"`，允许滚动至末行后一页的位置。设为`"off"`可禁止此行为                                                                                         | `"one_page"`         |
| vertical_scroll_margin | 滚动时在光标上下方保留的行数。设为`0`可允许光标垂直移动至屏幕边缘                                                                                                | `3`                  |
| gutter.line_numbers    | 控制装订线中行号的显示。将`"line_numbers"`属性设为`false`可隐藏行号                                                                                                | `true`               |
| command_aliases        | 定义命令面板中命令别名的对象。可用于为常用命令定义快捷名称。具体示例请参阅下文说明                                                                                             | `{}`                 |

以下是一个修改后的设置示例：

```json [settings]
{
  // Disable cursor blink
  "cursor_blink": false,
  // Use relative line numbers
  "relative_line_numbers": true,
  // Hide the scroll bar
  "scrollbar": { "show": "never" },
  // Prevent the buffer from scrolling beyond the last line
  "scroll_beyond_last_line": "off",
  // Allow the cursor to reach the edges of the screen
  "vertical_scroll_margin": 0,
  "gutter": {
    // Disable line numbers completely:
    "line_numbers": false
  },
  "command_aliases": {
    "W": "w",
    "Wq": "wq",
    "Q": "q"
  }
}
```

`command_aliases` 属性是一个独立对象，用于将按键或按键序列映射到 vim 模式命令。上例定义了多个别名：`W` 对应 `w`，`Wq` 对应 `wq`，`Q` 对应 `q`。

## 正则表达式差异

Zed 使用的正则表达式引擎与 Vim 不同。这意味着在某些情况下需要使用不同的语法。以下是最常见的差异：

- **捕获组**：Vim使用`\(`和`\)`表示捕获组，而在Zed中则对应`(`和`)`。相反，在Vim中`(`和`)`表示字面括号，但在Zed中需转义为`\(`和`\)`。
- **匹配项**：替换时，Vim使用反斜杠加数字表示匹配的捕获组，例如`\1`。Zed则采用美元符号，因此Vim中用`&`表示完整匹配时，Zed的语法为`$&`。编号捕获组同理：Vim的`\2`对应Zed的`$2`。
- **全局选项**：Vim默认每行仅匹配首个结果，需在查询末尾添加`g`来匹配全部。Zed的正则搜索默认即为全局匹配。
- **大小写敏感**：Vim通过`\c`标记开启不区分大小写搜索。Zed可在模式开头使用`(?i)`，或通过快捷键{#kb search::ToggleCaseSensitive}切换大小写敏感。

> **注意**：为便于过渡，当您编写 Vim 风格的替换命令时，命令面板会自动修正括号并替换分组，`:%s//`。因此，Zed 会将 `%s:/\(a\)(b)/\1/` 转换为搜索 "(a)\(b\)" 并替换为 "$1"。

有关 Zed 正则表达式引擎支持的完整语法，请参阅 [regex crate 文档](https://docs.rs/regex/latest/regex/#syntax)。
